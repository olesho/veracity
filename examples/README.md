# examples

`greeter-go/` is a **sample single-Go project generated by `harness`**, committed
so you can see exactly what a managed project looks like and run the flow against
it. It was produced with:

```sh
harness setup --config - <<'JSON'
{ "layout": "single", "preset": "standard",
  "capabilities": { "agents": ["claude"], "gitHooks": true, "skills": true },
  "projects": [{ "name": "greeter", "language": "go", "modulePath": "example.com/greeter",
    "features": { "lint": true, "test": true, "markdown": true, "diagrams": true } }] }
JSON
```

then enriched with agent-written prose and rendered:

```sh
harness docs enrich --from - < summaries.json   # module + interface prose
harness docs render                             # writes docs/MODULES.md, modules.svg, modules.html
```

It is a **nested Go module** (`example.com/greeter`), so the parent harness
module's `go build ./...` / `go test ./...` / `golangci-lint` ignore it.

## Try it

```sh
cd examples/greeter-go
harness verify        # confirm the tree matches harness.lock.json
harness lint          # gofmt + go vet + golangci-lint
harness test          # go test
harness docs status   # what module/interface prose is fresh vs pending
harness docs render   # regenerate docs/MODULES.md + modules.{svg,html}
```

Open `docs/modules.html` in a browser to see the module card and the `Greeter`
interface boundary block with its methods.

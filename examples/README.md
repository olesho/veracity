# examples

`greeter-go/` is a **sample single-Go project generated by `veracity`**, committed
so you can see exactly what a managed project looks like and run the flow against
it. It was produced with:

```sh
veracity setup --config - <<'JSON'
{ "layout": "single", "preset": "standard",
  "capabilities": { "agents": ["claude"], "gitHooks": true, "skills": true },
  "projects": [{ "name": "greeter", "language": "go", "modulePath": "example.com/greeter",
    "features": { "lint": true, "test": true, "markdown": true, "diagrams": true } }] }
JSON
```

then enriched with agent-written prose and rendered:

```sh
veracity docs enrich --from - < summaries.json   # module + interface prose
veracity docs render                             # writes docs/MODULES.md, modules.svg, modules.html
```

It is a **nested Go module** (`example.com/greeter`), so the parent veracity
module's `go build ./...` / `go test ./...` / `golangci-lint` ignore it.

## Try it

```sh
cd examples/greeter-go
veracity verify        # confirm the tree matches veracity.lock.json
veracity lint          # gofmt + go vet + golangci-lint
veracity test          # go test
veracity docs status   # what module/interface prose is fresh vs pending
veracity docs render   # regenerate docs/MODULES.md + modules.{svg,html}
```

Open `docs/modules.html` in a browser to see the module card and the `Greeter`
interface boundary block with its methods.
